# Windows 便携版发布流程

当前工作仅准备开源配置与本地预发布包，不会自动推送、创建公开 Release 或改变仓库可见性。

## 构建与验收

1. 在 `src/app/AppVersion.h` 更新版本，补充 `CHANGELOG.md`。标签应为同版本 `vX.Y.Z`。本轮为 `2.2.0`，尚未公开发布。
2. 使用干净检出和受支持的依赖执行 Debug、Release 构建、回归以及编码检查。Windows Actions 从官方固定 OpenCV 提交构建共享库，使用 Qt 5.15.2；工作流首次远端运行结果需要在推送后验证。
3. 人工检查 100%、150%、200% Windows 缩放及多屏切换，确认字体、圆角、窗口边缘缩放、两侧箭头、像素坐标、RGB/灰度切换和 ROI 计数。
4. 核对真实图片拖放、损坏文件恢复、保存、中文路径、语言切换及空白/小窗口。自动 offscreen 回归不能替代这些桌面检查。
5. 使用 `scripts/package-release.ps1` 生成 ZIP 与 `.sha256`，在无 Qt/OpenCV 开发环境的 Windows 上解压启动并打开 PNG/JPEG/BMP/TIFF。检查所有 DLL 依赖，不能只测试开发目录。

## 开源与许可

- 本轮采用 MIT 许可用于自有代码。确认拥有对外开源相关代码、文档、图标与样例图片的权利。
- 检查包括历史 Git 提交在内的敏感信息、本机路径、私人图片和第三方二进制。仓库含历史 OpenCV 导入库；本轮未重写历史，迁移或清理方案应另行决定。
- 核对 `THIRD_PARTY_NOTICES.md`，将**实际版本**的 Qt/OpenCV 源码获取说明、构建参数、修改补丁和归属文件与便携包一起发布。通用许可证原文不取代依赖中的所有第三方声明。
- 评估 Qt 5.14/5.15 和 OpenCV 4.5.5 的维护状态及升级计划。本地兼容性测试通过不代表这些旧依赖已完成安全审计。
- 确认仓库公开范围、私密漏洞报告、默认分支保护和 Actions 权限。配置文件不会替代 GitHub 仓库设置。

## 正式发布

上述验收完成后，再将已提交版本推送到仓库并推送同名标签。CI 的职责是构建、测试和上传待验收产物，默认只有读取仓库权限，不自动创建公开 Release。

在 GitHub Releases 先创建草稿，附上变更说明、Windows x64 ZIP、SHA-256 文件和源码/依赖材料，核对后公开。无代码签名版本应如实说明，不能宣称安装程序、自动更新或签名已完成。

### 校验下载

```powershell
Get-FileHash .\ImageViewer-2.2.0-windows-x64.zip -Algorithm SHA256
```

与同名 `.sha256` 文件核对。SHA-256 用于完整性校验，不替代代码签名或可信发布渠道。
